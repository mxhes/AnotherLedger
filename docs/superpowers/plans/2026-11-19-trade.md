# Trade section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record auction house events and player trades per realm, show sales statistics in a new Trade tab, and add an Own sales price source after the LootLedger scan.

**Architecture:** A pure `Trade.lua` holds the store (per realm, like `Scan.lua`), the rules (trade kinds, mail dedupe, post matching, gold split) and the statistics. `Core.lua` gets a trade section that reads the client (mail, auction house calls, chat, trade window) and feeds `Trade`. `Sources/Sales.lua` answers prices from `Trade`; `View.lua` builds the two Trade sub-tab views; `UI/Tabs.lua` defines the tab and `UI/TradePeriod.lua` the 7 / 30 / All switch.

**Tech Stack:** Lua 5.1 (WoW Forever client, Interface 16001), plain-Lua tests (`lua tests/run.lua`).

**Spec:** `docs/superpowers/specs/2026-11-19-trade-design.md`

## Global Constraints

- Lua 5.1 only: no `goto`, `//`, `table.unpack`, integer-only APIs.
- Files outside `UI/` are pure; client calls are injected or looked up at call time. `UI/` touches globals only inside functions.
- Every text through `ns.L` (`local L_X = L["Text"]` at file top), German in `Locales/deDE.lua`.
- Options: default in `DB.defaults.settings`, `label` at most 24 characters, a `tooltip`, validated by `Options.normalize`, read with `Options.get`.
- Money in copper; items keyed by `LootParse.itemKey(link)` (else the item ID), as `Scan.lookup` does.
- Every unconfirmed client API: `UNVERIFIED (check in client)` comment plus a line in `docs/CHECKLIST.md`.
- New `.lua` files go in `LootLedger/LootLedger.toc` and the layout table in `docs/DEVELOPMENT.md`.
- Price order stays TSM, Auctionator, LootLedger scan, Own sales.
- Commits: `feat:` / `fix:` / `docs:` one-line summary plus a short body, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. The same sale mail read again, by another character, or as temporary and then final invoice: exactly one sale (Task 2 tests).
2. A commodity post that sells in several parts: one sale per mail, the post's amount shrinks, the rate counts units (Task 2, Task 3 tests).
3. A sale mail with no matching post (posted before LootLedger had this, or on a character never logged in since): the sale still counts by name; it feeds the price source only when an item ID could be found (Task 2 test).
4. A trade where the partner gives items and gold, or nothing at all: logged as "trade", never a sale (Task 1 test).
5. Realm key not known yet when an event comes: nothing is recorded, nothing errors (Task 5 wiring test).

**Interfaces:**
- Consumes: `ns.LootParse.itemKey(link)`.
- Produces (all on `ns.Trade`):
  - `Trade.DAY = 86400`, `Trade.LOG_DAYS = 90`.
  - `Trade.bucket(db, realmKey, create) -> bucket | nil`: `db.trade[realmKey] = { log = {}, totals = {}, posts = {}, pending = {}, mails = {} }`, same rules as `Scan.bucket`.
  - Entry shape (plain table, short fields; *Ruling: plain tables instead of packed strings, the log is bounded by Trade log kept*): `{ t, kind, key, id, name, n, gold, cut, market, who, char, split, out, ["in"], goldOut, goldIn }`. `kind` is one of `"post"`, `"cancel"`, `"expire"`, `"sale"` (auction), `"tsale"`, `"tbuy"`, `"trade"`. `gold` is the total before the cut (sale, tsale, tbuy, post = unit price x n); `cut` the auction house cut; `market` the market price per unit on that day or nil; `split = true` when the gold of a trade sale was split between item kinds; `out` / `in` = `{ { key, id, name, n }, ... }` for trades.
  - `Trade.add(bucket, entry)`: appends to `log` and updates `totals[key]` = `{ posted, sold, soldAH, expired, cancelled, gold, cmpN, cmpSale, cmpMarket }` (amounts in units; `gold` earned = gold minus cut; `cmp*` only for sales with a market and without `split`). Entries without `key` count in no totals.
  - `Trade.classify(out, inItems, goldOut, goldIn) -> "tsale" | "tbuy" | "trade"`.
  - `Trade.prune(bucket, now, keepDays)`: drops log entries older than `keepDays` days, posts older than 2 days, pending marks older than 2 days, mail keys past their expiry. Totals stay.

### Task 2: Posts, sold marks and mail recording

**Files:**
- Modify: `LootLedger/Trade.lua`, `tests/test_trade.lua`

**Interfaces:**
- Consumes: Task 1.
- Produces:
  - `Trade.addPost(bucket, post)`, `post = { t, key, id, name, n, unit }`: logs a `"post"` entry and keeps an open post in `bucket.posts`.
  - `Trade.cancel(bucket, c)`, `c = { t, key, id, name, n }`: logs `"cancel"`, takes `n` off the newest open post of that key.
  - `Trade.markSold(bucket, name, now, market)`: keeps `{ name, t, market }` in `bucket.pending` (no sale yet).
  - `Trade.mailKey(m) -> string`: from `m.subject, m.sender, m.money, m.kind, m.name, m.who, m.gold, m.n` and `m.expires` rounded down to the minute.
  - `Trade.saleKey(m) -> string`: `name|who|gold|n` (joins the temporary and the final invoice).
  - `Trade.JOIN_WINDOW = 7200` (seconds within which a second invoice with the same sale key is the same sale).
  - `Trade.recordMail(bucket, m, now, marketAt) -> entry | nil`, `m = { kind = "sale"|"expire"|"cancel", subject, sender, money, expires, name, who, gold, cut, n, key, id, char }` (`key`/`id` set for expire and cancel from the attachment link; for a sale set only when the client could map the name to an ID). `marketAt(key, id) -> copper per unit | nil` is called only when no pending mark gives the market. Returns the new entry, or nil when the mail key is known, a sale with the same sale key came within `JOIN_WINDOW`, or `kind == "cancel"` (already counted at the auction house; only the mail key is kept).
  - A sale takes `key`/`id` from the newest open post with the same `name` when `m.key` is nil, and takes `n` off that post; an expire takes `n` off the newest open post of its key; the market comes from the oldest pending mark of that name (removed), else `marketAt`.

### Task 3: Statistics, gold split and the sale price

**Files:**

**Interfaces:**
- Consumes: Tasks 1 and 2.
- Produces:
  - `Trade.splitGold(items, gold, marketOf) -> { copper per item, same order }`: by each item's `market x n` share; equally per unit when any item has no market; the parts add up to `gold` exactly (the rest goes to the last item).
  - `Trade.addTrade(bucket, snap, now, marketOf)`, `snap = { out, ["in"], goldOut, goldIn, who, char }`: logs one entry of `Trade.classify`'s kind. A `"tsale"` with one item kind logs `kind = "tsale"` with `key, id, name, n, gold = goldIn, market`; with several kinds it logs one `"tsale"` per kind with its split gold and `split = true`. `"tbuy"` and `"trade"` log one entry with `out`, `in`, `goldOut`, `goldIn` (no totals).
  - `Trade.itemStats(bucket, since, now) -> list` of `{ key, id, name, sold, soldAH, gold, expired, cancelled, rate, vsMarket, sales }`: from the log entries with `t >= since` when `since` is a number, from `totals` when `since` is nil (`sales` always from the log, newest first). `rate = soldAH / (soldAH + expired + cancelled)` or nil when that sum is 0; `vsMarket = cmpSale / cmpMarket - 1` (a fraction) or nil without compared sales. Only items with `sold > 0` or auction events are listed. Name-only sales (no key) are grouped by `name`.
  - `Trade.salePrice(bucket, itemID, link, now) -> unitPrice, age | nil`: the amount-weighted average of `gold / n` over the `"sale"` and `"tsale"` log entries of the item key without `split`; age = `now - t` of the newest of them.

### Task 5: Core trade section (client reads and events)

**Files:**
- Modify: `LootLedger/Core.lua`, `tests/test_wiring.lua`, `docs/CHECKLIST.md`

**Interfaces:**
- Consumes: Tasks 1-4; `Scan.currentRealmKey()`; `ns.prices:marketPrice`.
- Produces:
  - `Core.tradeBucket(create) -> bucket | nil` (`Trade.bucket(ns.db, Scan.currentRealmKey(), create)`); every recording below does nothing when it is nil.
  - `Core.marketAt(key, id, link) -> copper | nil` = `ns.prices:marketPrice(id, link, L["Own sales"])`.
  - The data kind `"trade"` is signalled after each recording the same way `Inventory` signals `"bags"` (find it by `watches`), so the Trade tab redraws.
  - At login: `Trade.prune(bucket, now, Options.get("tradeLogDays"))`.
- Client calls, each with `UNVERIFIED (check in client)` and a CHECKLIST line:
  - **Posting:** `hooksecurefunc(C_AuctionHouse, "PostItem", fn(itemLocation, duration, quantity, bid, buyout))` and `"PostCommodity", fn(itemLocation, duration, quantity, unitPrice)`; the link from `C_Item.GetItemLink(itemLocation)`; unit price = `buyout / quantity` (PostItem without buyout: `bid / quantity`). Hooked once, when the auction house UI is loaded (`ADDON_LOADED` of `Blizzard_AuctionHouseUI` or at login when `C_AuctionHouse` exists).
  - **Cancelling:** `hooksecurefunc(C_AuctionHouse, "CancelAuction", fn(auctionID))`; the item from the owned auction with that ID (`C_AuctionHouse.GetNumOwnedAuctions`, `GetOwnedAuctionInfo(i)` -> `auctionID, itemLink, quantity`), read at the hook.
  - **Sold mark:** `CHAT_MSG_SYSTEM` text matching `ERR_AUCTION_SOLD_S` (turned into a pattern with `%s` -> `(.+)`), then `Trade.markSold(bucket, name, now, market)` with the market from the item ID the client gives for the name (`C_Item.GetItemInfoInstant(name)`), else nil.
  - **Mail:** on `MAIL_INBOX_UPDATE`, for `i = 1, GetInboxNumItems()`: `GetInboxHeaderInfo(i)` (sender, subject, money, `daysLeft`) and `GetInboxInvoiceInfo(i)` (`invoiceType, itemName, playerName, bid, buyout, deposit, consignment, ..., count`). `invoiceType == "seller"` or `"seller_temp_invoice"` -> a sale mail; a subject matching `AUCTION_EXPIRED_MAIL_SUBJECT` / `AUCTION_REMOVED_MAIL_SUBJECT` -> expire / cancel with the item from `GetInboxItemLink(i, 1)` and its count from `GetInboxItem(i, 1)`. `expires = now + daysLeft * 86400`. Then `Trade.recordMail`.
