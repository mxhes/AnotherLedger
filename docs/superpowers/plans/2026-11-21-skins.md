# Skins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pickable border, background, button and line styles (plus a Sunken list box) with four skins that set them at once.

**Architecture:** The style data and every pure helper live in `Theme.lua` (`Theme.skins`, `Theme.skinParts`, the active picks in `Theme.style`). Options write the picks into `Theme.style` and call `Widgets.applySkin()`, which redraws every tracked backdrop, button and styled line and runs the hooks UI parts registered with `Widgets.onSkin`. Edges are drawn from 1 px flat textures; Grain, Leather, Stud and Dotted are addon `.tga` files drawn by `tools/render_skins.py`.

**Tech Stack:** Lua 5.1 (WoW Forever client, Interface 16001), plain-Lua test harness (`lua tests/run.lua`), luacheck, Python 3 + Pillow for the textures.

**Spec:** `docs/superpowers/specs/2026-11-21-skins-design.md`

## Global Constraints

- Lua 5.1 only (no `goto`, `//`, `table.unpack`); files outside `UI/` stay pure; `UI/` files touch WoW globals only inside functions.
- Classic (`skin = "classic"`: round / flat / bronze / gold / list box off) must look exactly like today.
- No layout or size changes: `Theme.sizes` budgets, header rows, row heights and insets unchanged; `tests/test_overflow.lua` must still pass.
- Skins never change colors; every style takes its colors from `Theme.colors` (panelTint, panelBorder, buttonFill / buttonEdge*, the line's own color).
- Opacity and brightness (`Window.paintLook`) apply to every border and background.
- Option labels at most 24 characters; every text through `ns.L` with the German text in `Locales/deDE.lua`.
- Texture paths without extension, under `Interface\\AddOns\\AnotherLedger\\Media\\Skins\\`; power-of-two sizes.
- An unconfirmed client call gets `UNVERIFIED (check in client)` and a `docs/CHECKLIST.md` line.
- Run `lua tests/run.lua` and `luacheck AnotherLedger` after every task; both clean.
- Work on branch `claude/skins`; commits `feat:` / `docs:` style with the attribution line.

## Review Focus

1. A saved value that is no longer a valid choice (typo, older version, a profile import) for `skinBorder` etc.: falls back to the chosen skin's part, never errors. Test in Task 3.
2. Switching border from Round to Bevel and back while the window is open: the line rectangles hide again and the tooltip edge comes back (no double frame). Test in Task 4.
3. Opacity 0 / brightness 2 with a non-round border: the edge lines fade / lighten like the backdrop border does today. Test in Task 4.
4. A profile switch (or profile import) with different skin picks: the window restyles at once. Test in Task 5.
5. Compact layout with Sunken list on: the box stays hidden in compact and comes back in full. Test in Task 5.

  - `Theme.edgeStuds(border) -> boolean` (true for gilded only).
  - `Theme.mix(a, b, t) -> color` (r, g, b linear mix, alpha of `a`).
  - `Theme.lineColors(lines, color, panel) -> main, second|nil`: gold -> `color`; groove -> `scaleColor(color, grooveDark)`, `scaleColor(color, grooveLight)`; plain -> `mix(color, panel, plainMix)` with gold removed (use `mix` toward `{0.5,0.5,0.5}` first, then toward panel; one formula, documented in a comment); dotted -> `color`. Alpha of `color` kept on both.
  - `Theme.skinScales = { edgeDark = 0.25, grooveDark = 0.35, grooveLight = 1.6, raisedLight = 1.8, raisedDark = 0.45, plainMix = 0.5, listBox = 0.6 }`.
  - `Theme.sizes.skinTile = 64`, `Theme.sizes.studSize = 10`, `Theme.sizes.listBoxPad = 3`.

**Interfaces:**
- Consumes: Task 1 helpers, `Theme.style`.
- Produces:
  - `Widgets.applyBackdrop(frame, opaque)`: `SetBackdrop(Theme.backdropSpec(style.border, style.background))`; creates once and then shows / hides `frame.skinEdges` (one rectangle of 4 one-pixel textures per `Theme.edgeRects` entry, at `Widgets.pixels(frame, inset)`, `BORDER` layer) and `frame.skinStuds` (4 `studSize` textures of `textures.skinStud` on the corners, `OVERLAY`). Calling it again restyles in place (no duplicate regions).
  - `Widgets.paintEdges(frame, border)`: colors the edge rectangles with `scaleColor(border, rect.shade)` (alpha of `border`) and the studs with `border`. `Window.paintLook` calls it with the same scaled color it gives `SetBackdropBorderColor`; `backdropColors` calls it too.
  - `Widgets.buttonColors(state, warn)` gains `light` = `scaleColor(fill, raisedLight)` and `dark` = `scaleColor(fill, raisedDark)`, swapped while pressed (hover lightens both by `BUTTON_HOVER`).
  - Buttons by `style.buttons` (`paint`): bronze = today; raised = bands hidden, backdrop fill `c.fill`, backdrop edge `c.edge`, inner frame edge hidden, four 1 px textures `b.raise` (top + left `light`, bottom + right `dark`) just inside the edge; flat = bands, inner and raise hidden, fill `c.fill`, edge `c.edge`. Create the raise textures lazily, once.
  - `Widgets.rule(parent, color, layer, alpha) -> texture`: a horizontal styled line, tracked `{ "rule", color, alpha }`. By `style.lines`: main color/texture from `Theme.lineColors`; groove adds `tex.groove` (one screen pixel high, right under the line, same width, `second` color); dotted uses `textures.skinDotted` with `SetHorizTile(true)` (UNVERIFIED (check in client)); others the flat texture with horizontal tiling off. `Widgets.setLineColor` works on rules too.
  - `Widgets.onSkin(fn)`: registers a restyle hook. `Widgets.applySkin()`: re-runs `applyBackdrop` on every tracked backdrop (keeping `opaque`), repaints buttons, restyles rules, runs the hooks, then `ns.UI.Window.applyLook()` when present.
  - Every new region is created inside functions (UI-file rule); initialize optional fields to `false` (fake frames answer unset fields with functions).
  - Missing-texture fallback (spec anti-goal): where `SetTexture` returns `false` (stud, dotted) hide the stud / use the flat line instead. The backdrop `bgFile` has no return value; Task 2's on-disk test is its guard.
